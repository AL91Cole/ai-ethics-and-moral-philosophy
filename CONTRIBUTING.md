# Contributing

This repository welcomes respectful critique, source corrections, philosophical disagreement, accessibility improvements, case studies, and proposals that make ethical commitments more testable.

## Before Contributing

Identify the kind of contribution:

- **Personal-position revision:** proposes a change to Al Cole's stated framework
- **Source analysis:** summarizes or critiques published work
- **Applied proposal:** connects ethics to a technical or governance design
- **Standards crosswalk:** maps a framework without claiming certification
- **Case study:** evaluates a real or proposed use in context

Do not present a personal opinion as consensus, an AI-generated statement as a verified source, a standards mapping as compliance, or a conceptual safeguard as an implemented control.

## Good Contributions

A useful proposal explains:

1. what should change;
2. why it matters;
3. who may benefit or be harmed;
4. which evidence or experience supports it;
5. how it affects dignity, autonomy, privacy, fairness, accessibility, accountability, and power;
6. what disagreement or uncertainty remains.

Criticism is welcome when it addresses ideas and evidence rather than attacking a person's identity or worth.

## Sources

- Prefer primary sources, peer-reviewed research, official standards, statutes, and direct documentation.
- Cite the exact source and link or identifier when available.
- Separate quotation from paraphrase and personal interpretation.
- Do not invent citations or imply that a source supports a claim it does not address.
- Mark access dates for sources likely to change.

## Accessibility

Use descriptive headings, plain-language summaries, meaningful link text, alt text for informative images, and tables only when they improve understanding. Avoid conveying meaning through color alone.

## Security Reports

Do not publish exploitable details, credentials, personal data, or evidence from a real incident in a public issue. Security concerns involving a related implementation should be reported through that repository's documented private security channel.

## Pull Request Checklist

- [ ] I identified the document type.
- [ ] I distinguished my interpretation from the source's position.
- [ ] I included sources for externally verifiable claims.
- [ ] I considered affected and marginalized people.
- [ ] I considered privacy, accessibility, misuse, and power.
- [ ] I stated important limitations and unresolved disagreement.
- [ ] I checked links, headings, and Markdown rendering.

## Protected-Core Changes

A contribution may challenge any protected principle, but no such change should be merged casually. A proposed core revision should include affected-party analysis, competing arguments, evidence, safeguards, governance review, version history, and a rollback plan.

Openness to revision and resistance to silent value overwrite are both necessary.
